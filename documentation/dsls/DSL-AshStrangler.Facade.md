# AshStrangler.Facade

An Ash resource with no storage of its own, giving a different vocabulary to
the rows of one source resource.

    defmodule MyApp.WorkItem do
      use Ash.Resource,
        domain: MyApp.Domain,
        data_layer: Ash.DataLayer.Simple,
        extensions: [AshStrangler.Facade]

      attributes do
        attribute :id, :uuid, primary_key?: true, allow_nil?: false, public?: true
        attribute :title, :string, public?: true
        attribute :state, :atom, public?: true, constraints: [one_of: [:new, :finished]]
        attribute :effort_minutes, :integer, public?: true
        attribute :licence_number, :string, public?: true, sensitive?: true
      end

      facade do
        source MyApp.Task            # the row source (an Ash resource)
        read_action :read            # the source's read action; default :read

        map :id, from: :id
        map :title, from: :name
        decode :state, from: :status, values: %{done: :finished}
        map :effort_minutes, from: :estimate_minutes
        map :licence_number, from: :number

        hide :internal_notes, because: "Not part of this vocabulary."
        defer :legacy_ref

        # Writes: each is a generic action on the facade that runs ONE named
        # source action.
        write :finish, via: :complete, sets: [state: :finished]              # by value
        write :set_estimate, via: :set_estimate, accepts: [:effort_minutes]  # by acceptance
      end
    end

A facade reads by calling the source's read action as the caller, and each
`write` runs one named source action as the caller. It declares no rule
about who may see or change anything: the source's policies and field
policies decide, because every fact keeps one record, on the source. The
mapping grammar is the strangler's (`AshStrangler.Dsl.mapping_entities/0`),
so a lens means the same thing over a view and over an Ash source.

| | |
|---|---|
| what a read does | `AshStrangler.Facade.Read` |
| what a write does | `AshStrangler.Facade.Write` |
| what the declaration *means* | `AshStrangler.Facade.Info`, over `AshStrangler.Lens` |
| what is *legal* | the modules under `AshStrangler.Facade.Verifiers` |
| what can be *proven* about it | `AshStrangler.Obligations.over/3` |

Offset pagination only, and no count: Ash reports none for a manual read.
One write is one source action. `as_of` is read-only on a facade — forwarded
over a temporal source, refused over any other — and refused on every write.
A hop chain over a facade source is read hop by hop: see
`AshStrangler.Facade.Info.hops/1`.

### facade.decode
```elixir
decode attribute
```


A declared bijection between a legacy value set and an attribute value set.

Both directions come from **one** declaration, which is the whole thesis. The
cautionary tale is Rust's `strum` against `serde`, whose `serialize_all` and
`rename_all` disagree by default, so one enum acquires two non-matching
encodings and round-tripping quietly breaks.

Checked at compile time: injectivity, totality over the legacy value space,
and surjectivity onto the attribute's own `one_of` constraint — read off the
resource and the twin, not restated here. Where a value space is unbounded the
check is re-emitted as a SQL assertion for `mix ash_strangler.check` to run
against real data.




### Examples
```

  "active"    => 0,
  "passive"   => 1,
  "pending"   => 2,
  "suspended" => 3,
  "deleted"   => 4
}
```

### facade.concat
```elixir
concat attribute
```


Several legacy columns joined by a separator. The reverse is `split_part`.

Invertible only with a separator provably absent from every operand — the
degraded form of Boomerang's regex-ambiguity condition (POPL 2008). Absence
cannot be decided from the schema either, so it becomes a SQL assertion:
`mix ash_strangler.check` counts the rows in which any operand contains the
separator, and any count above zero means the reverse is wrong for those rows.

If that count is not zero, the honest mapping is a `map` with
`read_only? true` — which is what `full_name` is in this package's own
fixtures, because `'de la Cruz'` splits wrong and no separator fixes it.

### facade.write
```elixir
write name
```


One write: a generic action on the facade that runs ONE named source action,
as the caller. `sets:` names facade attributes and the values they take (put
through the lens at compile time and checked against the source action's own
`set_attribute` changes); `accepts:` names facade attributes whose argument
value is put through the lens. At least one of the two is required.




### Examples
```
write :finish, via: :complete, sets: [state: :finished]
```

```
write :set_estimate, via: :set_estimate, accepts: [:effort_minutes]
```



### Arguments

| Name | Type | Default | Docs |
|------|------|---------|------|
| [`name`](#facade-write-name){: #facade-write-name .spark-required} | `atom` |  | The name of the facade's generic action. |
### Options

| Name | Type | Default | Docs |
|------|------|---------|------|
| [`via`](#facade-write-via){: #facade-write-via .spark-required} | `atom` |  | The source's update action this write runs. One write is one source action. |
| [`sets`](#facade-write-sets){: #facade-write-sets } | `keyword` | `[]` | Facade attribute to value, put through the lens and checked against `via:`. |
| [`accepts`](#facade-write-accepts){: #facade-write-accepts } | `list(atom)` | `[]` | Facade attributes accepted as arguments of the generic action. |
